{%- comment -%} The contents page at /docs/. A card per section, not a list of every page. Three reasons: 1. It scales. Listing every page inline is fine with one section and unreadable with four. 2. The section landing pages are hand written in the docs repo, with their own tables describing each page. Repeating that list here would duplicate a better version of it. 3. The sidebar already carries the full tree on every docs page, so nobody needs an exhaustive list to get around. Sections come from the collection itself, and names and blurbs from _data/doc_sections.yml, falling back to a title-cased folder name so a new folder in the docs repo renders sensibly rather than blank. Nothing here needs editing when documentation is added.
